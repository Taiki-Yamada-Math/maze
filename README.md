# 手描き迷路ソルバー

白い紙に手描きした迷路をスキャンして読み込むと、Python がグラフに変換し、探索アルゴリズムで解く様子を見られるウェブアプリです。

画像処理と探索はすべて Python（`solver.py`）で行います。ブラウザの中で Python を動かす [Pyodide](https://pyodide.org/) を使っているので、サーバーは不要で GitHub Pages にそのまま置けます。

## 使い方

1. 白い紙に、濃いペンで迷路を描きます。
2. スキャンするか、真上から撮影します（JPEG か PNG）。
3. 「画像を選ぶ」で読み込むか、画面にドロップします。
4. 迷路の上をクリックして、スタートとゴールを置きます。
5. アルゴリズムを選んで「探索して解く」を押します。

画像がなくても「サンプル迷路で試す」で動きを確かめられます。

### うまく読み取るコツ

- 鉛筆より、サインペンやボールペンなど濃いペンが確実です。
- 通路は線の太さより十分広くとってください。
- 線の多少のかすれや途切れは自動でふさぎます。すり抜けてしまうときは「かすれの補修」を上げます。
- 紙の汚れや用紙のふちの影は自動で取り除きます。

## しくみ

1. **線を取り出す** 各画素が周りの紙よりどれだけ暗いかを求め、大津の方法でしきい値を決めて二値化します。影や照明ムラに左右されません。
2. **格子にする** 画素を小さなセルにまとめます。迷路が細かいほど自動で格子を細かくします。
3. **かすれをふさぐ** 通路の幅を推定し、それより十分小さい隙間だけを壁の膨張でふさぎます。
4. **グラフにする** 通路のセルをノード、隣り合う通路のセル同士（斜めを含む）を辺とします。
5. **探索する** スタートからゴールまでを探索し、調べた順番と経路を画面に返します。

| アルゴリズム | 特徴 |
|---|---|
| 幅優先探索（BFS） | 近いところから順に広げる。歩数が最小の経路を見つける |
| 深さ優先探索（DFS） | 行けるところまで進んで戻る。最短とは限らない |
| ダイクストラ法 | 壁に近い道ほど重いグラフで、合計コスト最小の経路を探す |
| A* | ダイクストラ法と同じ答えを、ゴールまでの見込み距離を手がかりに少ない探索で見つける |

BFS は壁ぎわを沿う経路、ダイクストラ法と A* は通路の中央を通る経路になり、辺に重みがあるかどうかの違いが目で見てわかります。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 画面。画像の読み込み、クリック、アニメーション |
| `solver.py` | Python。画像からグラフへの変換と、4 つの探索アルゴリズム |

## 手元で動かす

ブラウザで `index.html` を直接開くと `solver.py` を読み込めません。このフォルダで次を実行し、`http://localhost:8000` を開きます。

```bash
python -m http.server
```

`solver.py` はコマンドラインでも使えます（numpy と Pillow が必要です）。

```bash
python solver.py maze.png --start 40,30 --goal 900,650 --algo astar -o solved.png
```

## GitHub Pages で公開する

1. `index.html`、`solver.py`、`README.md` をリポジトリの**いちばん上（直下）**に置きます。フォルダに入れると公開 URL が 404 になります。
2. Settings → Pages で、Source を「Deploy from a branch」、Branch を `main` と `/ (root)` にして保存します。
3. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で公開されます。

## プライバシー

計算はすべてブラウザの中で行われ、画像が外部に送られることはありません。
